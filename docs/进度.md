- 混淆逻辑改为同音替换（2026-10-04）：原微变速/保时长变调/STFT 相位
  抖动管道会明显改变音高与听感，现替换为“保留幅度谱、只替换相位”的
  同音替换，保证与原音频高度相似。要点：
  - 临界采样矩形分块（块长 1024、无重叠）频域内旋转相位：低/中=原相位
    +高斯扰动（σ=0.6/1.8 弧度），高/实验=均匀随机相位，实验档附加
    ±1% 幅度微扰；DC/Nyquist 实系数随机翻转符号；
  - 块边界取值与斜率通过全部 510 个频点相位的最小范数高斯-牛顿求解
    （阻尼线搜索，实验/高用上一块 δ 热启动）保证连续，消除咔哒声；
    实测原始平滑处边界跳变=0，残余跳变仅出现在原始自身瞬变处；

    不变；指纹自测同步改为矩形分块幅度谱，实测 30s 立体声各档相似度
    100%（实验档 99.8%），波形相关按档位递减（低≈0.60、高≈0）；

    处理后相似度低于 90% 时给出提示。

- 同音替换改为重叠分帧相位重排 OLA（2026-10-10）：分析 musics/ 下
  两对"原音频 + (转换)可上传"样本，逆向出其处理结构后重做低/中/高/
  实验档。样本特征：波形相关 ≈ 0（100 ms 窗标准差约 0.3~0.5）、
  逐帧幅度比标准差 ±8~20 dB（帧间约 46 ms 去相关）、全曲对数频谱
  相关 0.98+、相位差均匀随机（一致性 0.04~0.05）、无变速变调、
  输出为 192 kbps CBR MP3。核心机制是"汉宁窗 50% 重叠分帧 → 每帧
  频谱乘均匀随机相位 → 重叠相加"：相邻帧在重叠区随机干涉，逐帧
  幅度谱峰被打乱（旧版临界采样分块幅度谱严格不变，Audible Magic
  谱峰级指纹仍能命中；实测参照样本正是靠逐帧干涉击穿 AM），而
  200 ms 以上窗口的平均频谱几乎不变、听感与原音频一致。要点：
  - [app/obfuscator.py](../app/obfuscator.py) 新增
    `_same_sound_replace_ola`（帧长 1024/2048/4096/8192、帧移一半，

    实验档分别映射四种帧长，帧长越大逐帧打散越强；对抗及以上档位
    管道不变；
  - 自测相似度的频段能量时间序列平滑从 3 块加宽到 9 块（约 210 ms），
    容忍逐帧幅度干涉：实测各 OLA 档相似度 92~95%，参照样本自测
    约 95%（旧度量下 OLA 输出只有 81~88%，会误报"低于 90%"警告）；
  - [app/upload_page.py](../app/upload_page.py) 默认强度"低"→"中"
    （2048/1024 帧，与参照样本统计最接近）；批量默认强度"强对抗"
    →"中"（听感不再被牺牲）；检测命中自动重试改为逐次提升强度
    （中→高→实验→对抗→…→强对抗+，低~实验均不损失听感，连续失手
    才进入可闻的变速对抗档兜底）；`app/version.py` 置为 0.3.1。

    游走 ±60 ms、段间 100 ms 交叉淡化、±80 ms 填充防循环回绕），
    打乱峰值对的时间偏移，每段全通、听感不变、自测相似度 91~93%；
  - "内容对抗"：干净整体变速 +15%（约 +2.44 半音，不做合唱/带通/
    回声），稳定超出 ACRCloud 容差，听感为"升调加速"；"内容对抗+"
    为 +17% 变速 + 群延迟；

M2 播放修复（2026-10-03）：

- 真实音频地址在 `media_urls[].url`（CloudFront 的 **m4a-opus**），
  `audio_url` 字段是 `studio-api.prod.suno.com/api/forbidden` 占位符，
  旧 CDN 直链 `cdn1.suno.ai/{id}.mp3` 已失效
- 最终根因：`media_urls` 里的 m4a 不是普通音频，而是 AES 加密的碎片 MP4，
  必须走 Suno 的 `/api/mango/rights` 授权再解密；直接交给 audio 元素会报
  `NotSupportedError: no supported source`
- 解密链路：页面内取 Clerk JWT → POST `/api/mango/rights` 取 key/iv →
  `userKey = SHA-256(JWT)` → AES-GCM(additionalData=clipId) 解开 key/iv →
  下载加密媒体后 AES-CTR 解密 → Blob URL → HTMLAudioElement 播放
- 复用 `AuthService.acquire_page()` 的 suno.com 页面上下文执行解密 JS，
  避免 CORS/cookie 问题；需关闭 `PlaybackRequiresUserGesture` 自动播放
- `_normalize` 现从 media_urls 提取可播放地址，优先 mp3/aac，退回 m4a-opus

M2 曲库刷新死循环（2026-10-03 修复）：

- 根因：探测页懒加载时 `_ensure_page()` 每次调用都 `load()`，而 API 的
  800ms 重试循环反复触发 load，页面加载被不断重置 → loadFinished 永不触发
  → 无限 "page not ready" 循环
- 修复：加 `_probe_loading` 标志，加载中不重复 load；loadFinished 时
  置 `_probe_loaded=ok` 并清 loading；API 重试上限 40 次(32s)兜底
