M2 播放修复（2026-10-03）：

- 真实音频地址在 `media_urls[].url`（CloudFront 的 **m4a-opus**），
  `audio_url` 字段是 `studio-api.prod.suno.com/api/forbidden` 占位符，
  旧 CDN 直链 `cdn1.suno.ai/{id}.mp3` 已失效
- 最终根因：`media_urls` 里的 m4a 不是普通音频，而是 AES 加密的碎片 MP4，
  必须走 Suno 的 `/api/mango/rights` 授权再解密；直接交给 audio 元素会报
  `NotSupportedError: no supported source`
- 解密链路：页面内取 Clerk JWT → POST `/api/mango/rights` 取 key/iv →
  `userKey = SHA-256(JWT)` → AES-GCM(additionalData=clipId) 解开 key/iv →
  下载加密媒体后 AES-CTR 解密 → Blob URL → HTMLAudioElement 播放
- 复用 `AuthService.acquire_page()` 的 suno.com 页面上下文执行解密 JS，
  避免 CORS/cookie 问题；需关闭 `PlaybackRequiresUserGesture` 自动播放
- `_normalize` 现从 media_urls 提取可播放地址，优先 mp3/aac，退回 m4a-opus

M2 曲库刷新死循环（2026-10-03 修复）：

- 根因：探测页懒加载时 `_ensure_page()` 每次调用都 `load()`，而 API 的
  800ms 重试循环反复触发 load，页面加载被不断重置 → loadFinished 永不触发
  → 无限 "page not ready" 循环
- 修复：加 `_probe_loading` 标志，加载中不重复 load；loadFinished 时
  置 `_probe_loaded=ok` 并清 loading；API 重试上限 40 次(32s)兜底

  （`#card QLabel#avatar`）恢复
- 同理 `#sidebar QLabel` 也需背景透明

## 待办与已知问题

- [x] Google 拒绝内嵌 WebView 登录 "Couldn't sign you in"（2026-10-03）：
      Google 安全策略封禁嵌入式浏览器 OAuth，非代码 bug。应对：
      ① 登录窗口改用 Discord/邮箱方式；② 账户页新增"导入 Cookie"兜底
      。注意：`__session` 是 HttpOnly，`document.cookie` 读不到——
      必须从 DevTools 网络面板复制请求的 Cookie 头；导入时校验
      是否含 `__session`，缺失则拦截提示
- [x] 登录成功但界面显示未登录（2026-10-03 修复）：根因是
      `runJavaScript` 不等待 Promise，async 检测脚本永远返回空。
      修复：两段式执行（启动任务写 `window.__chilliResult`，1.5s 后读取）。
- [x] window.Clerk 不存在导致检测失败（2026-10-03 修复）：新版 Suno 页面
      不再暴露 window.Clerk。**弃用 Clerk 方案**，改用
      QWebEngineUrlRequestInterceptor 拦截页面发往 studio-api.suno.ai 的
      请求，从请求头捕获 Bearer 令牌，再用令牌调 billing 接口取额度。
      令牌失效（401/403）自动置为未登录。探测页改为 suno.com/create。
      注意：账户邮箱暂无来源，界面显示"Suno 用户"
- [x] CI Windows 任务 make_logo.py 中文 print 崩溃（2026-10-03 修复）：
      runner 控制台为 cp1252，脚本输出已改 ASCII。
      经验：**所有脚本/日志输出用英文**，避免 CI 编码问题
- [x] 登录后反复弹 Cloudflare "Verify you are human"（2026-10-03 修复）：
